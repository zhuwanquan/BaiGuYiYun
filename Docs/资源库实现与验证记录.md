# 资源库实现与验证记录

日期：2026-09-23。Unity 版本：6000.6.0f1。

## 已实现的交付流程

1. 作者在 `Assets/_Game/ResourceLibrary/<scope>/<kind>/` 提供按规则命名的图片和音频。
2. 编辑器扫描文件名、路径、类型与 GUID，建立可按 scope、kind、关键字查询的元数据索引；解析所需作用域时再取得 Sprite 或 AudioClip。
3. 作者在 `Assets/_Game/Data/Routes/<routeId>/route.json` 填写选项、剧情、资源 ID 和演出动作。
4. 校验通过的已发布路线自动写入运行目录，选择菜单据此增加、更新或减少选项。新路线不需要手动制作资源目录或按钮。

命名规则见[美术资源命名与自动入库规则](美术资源命名与自动入库规则.md)，操作步骤见[多选项与美术接入指南](多选项与美术接入指南.md)。可复制模板在 `ResourcePreparation/Templates/route.example.json`；`initial-art-requirements.json` 是初始十二条娱乐线的美术交付清单示例，不是持续更新的数据库。实际资源要求以各路线当前 `requiredAssets` 和正文引用为准。

运行时按资源 ID 查找生成目录。新共享素材与原来的共享资源合并到 `shared-library.asset`；作者维护的 `shared.asset` 保持兼容。这里使用本地索引与字典查询，没有额外数据库服务。

## 验证结果

在独立 Unity 验收副本中完成检查，未向正式资源库加入测试图或测试路线。

| 检查 | 结果 | 覆盖范围 |
| --- | --- | --- |
| 纯名称解析契约 | 100 项通过 | 合法名称、路径一致性、字符与类型约束、错误扩展名、变体与重复 ID 语义 |
| Unity 资源库原生检查 | 11 项通过，0 项失败 | 自动 Sprite 导入、PNG/JPG/WAV、元数据查询导出、无需手工目录发布、共享与私有隔离、增删停用选项、坏命名、重复 ID、删图失效、草稿隔离、旧目录兼容、清理后的正式输出 |
| 原有 Unity 集成回归 | 24 项通过，0 项失败 | 14 项选择的滚动与导航、动态增减、剧情可达性、真实运行器通关、存档迁移与选择前快照恢复、娱乐奖励隔离 |
| 项目脚本编译 | 通过 | 26 个 Runtime 源文件、4 个 Editor 源文件，使用当前 Unity 的程序集与编译器 |

资源库原生检查入口为 `BaiguVN.Editor.ResourceLibraryChecks.RunBatch`，只允许在专用验收副本执行。测试图片和短音频由检查程序生成，结束后清理。原有集成回归入口为 `BaiguVN.Editor.RouteIntegrationChecks.RunBatch`。原始 JSON 结果随本次交付保留在工作区输出目录。

确认：发布数据仍只有 `canonical`；原共享目录内容未变；测试资源不残留。校验失败时保留上一份有效生成结果，并禁止用过期内容进入 Play 或构建。

## 当前内容边界

`perfect` 与 `fun_01` 至 `fun_12` 仍是草稿。十二条娱乐线已预留命名素材目录和立绘要求，后续可增加更多路线。没有用模板对白冒充完成的娱乐剧本，也没有生成正式美术。

新增可玩选项需要真实剧本整理成路线 JSON、引用有效资源并设为已发布。仅添加图片或普通 TXT 不会直接生成可玩的路线。已发布游戏需要重新构建才能获得工程中的更新；此次不包含联网更新机制。
