# 多选项与美术接入指南

新增可玩选项需要一条完整路线：选项文字、结构化剧本、对应美术与演出配置。新素材按规则命名并放进资源库，编辑器自动登记；剧本用资源 ID 引用。

## 当前内容状态

- `canonical` 为已发布的原著线，首次选择后进入原著正文。
- `perfect` 为完美线草稿；不打白骨精、靠机智解决的正式分支仍待接入。
- `fun_01`—`fun_12` 为十二条娱乐线草稿，未编造可玩的分支正文。每条预留新身份立绘要求，例如 `fun_01__portrait__wukong_identity__neutral`。
- 正式菜单只收集 `published` 路线，所以当前内容只提供原著选项；框架支持继续增加，不把上限定为十二条。
- 娱乐线可以正常通关、存读档和查看本轮历史；路线内不新增正式章节完成、跨轮已读、纪念或收藏，也不参加多结局与成就收集。

## 先准备两类源文件

| 位置 | 用途 |
| --- | --- |
| `Assets/_Game/Data/Story/baigu_story_v2.json` | 公共开场与原著正文 |
| `Assets/_Game/Data/Routes/<routeId>/route.json` | 一条路线的选项、节点、资源要求和发布状态 |
| `Assets/_Game/ResourceLibrary/<scope>/<kind>/` | 按命名规则放入新图片和音频 |
| `ResourcePreparation/Templates/route.example.json` | 可复制的完整路线 JSON 模板 |
| `Docs/美术资源命名与自动入库规则.md` | 文件名、类型、扩展名与错误示例 |

剧本需要整理为模板所示的 JSON。普通 TXT、策划说明或对白文档不会自动转换成可执行的节点与跳转；先将它们整理成 `route.json`，保留真实的分支正文。

## 新增一条路线的操作顺序

1. **停止 Play。** 在 Unity Project 窗口复制草稿目录并命名，例如 `fun_13`；也可新建该目录并使用[完整模板](../ResourcePreparation/Templates/route.example.json)。在文件管理器复制素材时不要保留重复的 `.meta` GUID。
2. **填写路线身份。** `routeId` 等于目录名；娱乐线用 `kind: "entertainment"`、`choiceGroupId: "first_encounter"`。填写 `title`、玩家看到的 `choiceText`、顺序 `order`，先保留 `status: "draft"` 与 `artReviewed: false`。
3. **补齐剧情。** `entryNode` 指向入口；`nodes` 的 ID 全局唯一，建议带路线前缀。对白用 `next` 连接，最终到达没有 `next` 的 `type: "end"`。发布时不能有断开的跳转、孤立专用节点或无法通关的节点。
4. **放入新美术。** 按下一节的目录和文件名放入图片、音频，返回 Unity 等待导入。复制模板时同步替换路线、节点和资源 ID 中的旧前缀。
5. **核对资源并用于剧情。** 打开 `BaiguVN → Resources → Query Resource Library`，筛选本路线，确认 ID、类型和路径。将 ID 填入节点及 `requiredAssets`，配置需要的变身或道具动作。
6. **确认发布。** 剧本、美术与必需音频都完成后，设 `artReviewed: true`、`status: "published"`，运行 `BaiguVN → Routes → Rebuild Published Catalog`，处理 Console 中的具体错误。
7. **进入游戏验收。** 在 `VNMain` 从正常入口走到首次选择，检查新增选项、画面和通关。验收后将源文件、相关 `.meta` 和生成输出一起做本地 Git 提交。

编辑器会在相关文件变化后排队重建；进入 Play 与构建前也会校验。无需手工制作按钮。已经运行的游戏或已经分发的版本，要在重新加载或重新构建后才能获得更新。

## 新素材如何命名并入库

```text
Assets/_Game/ResourceLibrary/<scope>/<kind>/<scope>__<kind>__<subject>__<variant>.<ext>
```

`scope` 为 `shared` 或所属路线 ID；文件名四段之间用双下划线。`subject`、`variant` 使用小写英文字母、数字与词间单下划线。路径严格保持 `scope / kind / 文件` 三层，名称中的 scope、kind 必须与目录一致。

例如，`fun_01` 预留立绘放在：

```text
Assets/_Game/ResourceLibrary/fun_01/portrait/fun_01__portrait__wukong_identity__neutral.png
```

该图的资源 ID 就是 `fun_01__portrait__wukong_identity__neutral`，不含目录和扩展名。把它填进 `portraitId`，或变身动作的 `assetId`，即可建立剧情引用。

| 类型 `kind` | 格式 | 常用剧本字段 |
| --- | --- | --- |
| `portrait` | PNG | `portraitId`、`transform.assetId` |
| `background`、`cg` | PNG／JPG／JPEG | `backgroundId`、`cgId` |
| `prop`、`effect` | PNG | `prop.assetId`、动作中的 `effectId` |
| `bgm`、`se`、`ambience` | WAV／OGG | `bgmId`、`seId`、`ambienceId` |

合规图片由导入流程配置为独立 Sprite。PNG 素材应按画面需要保留透明背景；自动登记无法判断表情、构图或透明效果是否正确。完整规则见[美术资源命名与自动入库规则](美术资源命名与自动入库规则.md)。

同名背景的 `.png` 与 `.jpg` 会得到相同 ID，属于重复，不能同时保留。`neutral_v2` 被视为新变体，不会自动覆盖 `neutral` 或被识别成“最新版本”。

## 查询、共享与旧资源兼容

资源查询窗口支持按 scope、kind 和文字筛选本地元数据。点击“导出索引 JSON”调用 `ExportMetadataIndex`，保存到项目的 `Library/BaiguVN/resource-library-index.json`；它是可重建的本地索引，不上传云端。

编辑器负责扫描与生成目录。运行时通过 `RouteResourceService.GetSprite(id, kind)` 等接口做字典精确查询；这里没有另建 SQL 服务。路线只能使用自己的专用资源与共享资源，不能依赖另一条娱乐路线的私有图片。

| 文件 | 维护方式 |
| --- | --- |
| `Assets/Resources/Routes/shared.asset` | 作者维护的旧共享目录，继续兼容现有共享美术与音频；旧素材无须重命名 |
| `Assets/Resources/Routes/shared-library.asset` | 自动合并旧共享目录与新命名库的 `shared` 素材，供运行时使用 |
| `Assets/_Game/Data/Routes/<routeId>/resource-catalog.asset` | 可选的旧手工登记兼容文件；新路线可完全省略，存在时会参与合并 |
| `Assets/Resources/Routes/<routeId>.asset` | 自动生成的已发布路线资源目录 |
| `Assets/Resources/Routes/index.json`、`generated-files.json` | 自动生成的选项目录及清理记录，不手改 |

自动命名库与手工登记不能重复同一个 ID，也不能用重名覆盖共享图。当前十二个草稿中的旧兼容目录已清空 `entries`；其新身份资源要求保留在 `requiredAssets` 中，等真实命名素材到位。

## 发布条件与选项增减

`requiredAssets` 是必须交付的资源要求；生成器还会扫描正文和动作中的所有引用。删除清单项不能绕过正文里的缺图。`artReviewed` 是作者确认美术的标记，勾选它不会自动完成剧情或补齐资源。

| 操作 | 重建后的变化 |
| --- | --- |
| 新增完整路线并设为 `published` | 自动增加对应选项 |
| 修改 `choiceText`、`order` | 自动修改文字和排序 |
| 改为 `draft` 或 `disabled` | 自动减少对应选项，源素材保留 |
| 移除路线的 `route.json` 或将内容包移出源目录 | 自动移除选项，清理已记录的生成副本 |

草稿可以没有正文、入口和美术，但 JSON 语法、路线 ID 与状态仍须正确。共享资源或已发布路线出现错误命名、重复 ID、缺图或坏跳转，会阻止整次发布并保留旧输出，同时阻止使用过期目录进入 Play 或构建。修复源文件后重新生成。

生成器不删除作者原图或 `shared.asset`。准备删除共享素材前先检查引用；下架选项与删除原图是两项不同操作。

## 演出与六个剧情节点

普通换图使用节点的 `portraitId`、`backgroundId`、`cgId`。需要变化过程时使用 `actions`：`transform` 换身份，可带 `effectId`；`flash` 闪白；`shake` 震动；`prop` 显示独立道具；`clearProp` 清除道具；`wait` 等待。

立绘槽位为左 `0`、中 `1`、右 `2`。动作的资源 ID 必须能在本路线或共享目录找到；详细字段以模板和 `Scripts/Runtime/Data/RouteData.cs` 为准。不要在同一节点对同一槽位同时填写直接换图的 `portraitId` 和变身动作，应拆成两个节点表达先后顺序。

第一次出手前的 `first_encounter` 自动收集整条路线。三次打妖怪和三次解释这些位置，可以在路线内部再写 `type: "choice"` 节点，省略 `choiceGroupId`，使用 `choices` 数组；每项填写自己的 `id`、`label`、`next`，并补齐目标正文和结尾。

内部选项继承当前路线身份。娱乐线即使汇入共用正文或结尾，也继续按娱乐线处理；不能返回 `first_encounter` 改选别的路线，或直接跳到另一条路线的私有节点。框架不会自动替作者写出六组分支剧本。

## 存档与资源换版

- `routeId` 不随菜单排序重编号；调整名称、按钮文字时保留它。节点与资源 ID 也不要重新分配给完全不同的内容。
- 重绘同一表情时保留文件名和 `.meta`；新增不同变体时使用新 ID，并更新剧情引用。节点结构或含义改变时更新 `contentRevision`。
- `contentRevision` 记录修订，不是单纯加一就强制回档。路线、节点和资源仍有效的存档可以继续恢复；剧情含义完全改变时应采用新节点 ID。
- 路线停用、删除，或存档节点／资源失效时，系统提示并尝试恢复首次选择前的完整快照；无有效检查点则返回开场。读取过程不覆盖原存档。
- 演出期间不能保存半成品画面。稳定后保存包含背景、立绘、CG、道具及音乐标识；读档恢复最终状态，不重放已结束的烟雾、闪白和震动。

## 每次接入后的验收方法

1. 查询新路线的素材元数据，核对 ID、scope、kind 与路径；试查不存在的 ID，确认不会默认为另一张图。
2. 重建目录后进入首次选择，检查数量、排序、长文案换行、滚动和键盘焦点；连点只进入一次，设置、历史与存档菜单仍能访问。
3. 走完整条路线，检查身份、表情、背景、CG、音频与变身节点；确认特效结束、道具清理及菜单暂停恢复正确。
4. 在稳定画面存读档，核对身份和道具；娱乐通关后检查正式章节、纪念、收藏与成就记录没有增加。
5. 保留测试存档，停用路线、重建并重新进入，检查选项减少与旧存档恢复；重新发布后检查选项恢复。
6. 在独立验收副本测试错误命名、同 ID 两种扩展名、发布路线缺图与坏跳转，确认整次发布被阻止、原输出保留。
7. 用十二条以上完整测试路线检查长列表，不把主工程空草稿直接发布来凑数；正式美术还需在目标设备检查字体、遮挡、音量与加载表现。

以上也是以后接入真实内容时的验收步骤。本轮已完成的自动检查见[资源库实现与验证记录](资源库实现与验证记录.md)；新分支的正式美术与演出仍需在接入时检查。
