# 多选项与美术接入指南

本指南对应当前工程的路线目录、动态选择界面、资源目录和演出播放器。新增选项的单位是一整条路线内容包：选项文字、可通关的剧本、对应美术和演出配置一起维护。

## 当前已经接入什么

- `canonical` 是当前唯一发布的原著线，从首次出手前的公共选择点进入原著后续剧情。
- `perfect` 是完美线草稿。机智解决、不打白骨精的正式剧本尚未编写，也没有发布为可玩选项。
- `fun_01` 至 `fun_12` 是十二条娱乐线草稿，每条预留了新身份立绘的资源要求。它们没有正式分支正文，没有制作成十二条可玩的故事。
- 正式菜单只显示通过校验的 `published` 路线。因此当前首次选择时只出现原著选项，符合目前的内容状态；按钮数量没有限制为十二个。
- 娱乐线可以正常到达结尾、保存、读取和查看本轮历史。它们不写入正式章节完成、跨轮已读、纪念或收藏记录，也没有接入多结局图鉴或成就收集。

## 文件放在哪里

| 位置 | 谁维护、有什么作用 |
| --- | --- |
| `Assets/_Game/Data/Story/baigu_story_v2.json` | 作者维护的公共开场及原著正文。文件名保留现状。 |
| `Assets/_Game/Data/Routes/<routeId>/route.json` | 作者维护该路线的选项、正文、资源要求和发布状态。 |
| `Assets/_Game/Data/Routes/<routeId>/resource-catalog.asset` | 在 Unity Inspector 中维护该路线专用资源的业务 ID、类型和实际对象引用。 |
| `Assets/_Game/Data/Routes/<routeId>/Art/`、`Audio/` | 建议放该路线的新图片、音频。文件夹可按内容需要建立。 |
| `Assets/Resources/Routes/shared.asset` | 作者维护的共享资源目录。用 Inspector 绑定师徒共用立绘、背景、音频等；生成器只读取、校验，不覆盖它。 |
| `Assets/Resources/Routes/index.json` | 自动生成的已发布路线目录，不能手改。 |
| `Assets/Resources/Routes/<routeId>.asset` | 自动生成的路线资源引用副本，不能手改。 |
| `Assets/Resources/Routes/generated-files.json` | 自动生成的文件清理记录，不能手改。 |

`shared.asset` 是生成目录中的作者维护项，和其他自动输出的处理方式不同。不要手工编辑这些 `.asset` 的 YAML 或 GUID；通过 Unity Inspector、Project 窗口维护源资源和共享目录。

原始图片和音频放在作者目录，不要为“能加载”而把所有路线素材塞进 `Resources`。`Resources` 中的文件会进入游戏资源构建范围，容易让停用内容仍随游戏分发；素材应通过共享目录或已发布路线的资源引用进入构建。运行时菜单先读取路线元信息，选中路线时再准备这条路线的资源。进入路线会加载该目录引用的素材，不是逐句话从网络下载。

## 新增、完成并发布一条路线

1. **停止 Play 模式。** 在 Unity Project 窗口复制一个草稿目录，或在 `Assets/_Game/Data/Routes` 下新建直属子目录，例如 `fun_13`。不要在文件管理器中复制后保留重复的 `.meta` GUID。
2. **设置路线身份。** `routeId` 必须等于目录名，以小写字母开头，只包含小写字母、数字、下划线或连字符；`kind` 填 `entertainment`，`choiceGroupId` 填 `first_encounter`。填写 `title`、玩家看见的 `choiceText` 和排列顺序 `order`，先保持 `status: "draft"`、`artReviewed: false`。
3. **接入剧本。** `entryNode` 指向入口；`nodes` 中每个节点 ID 全局唯一，建议以路线 ID 开头。对白节点填写 `next`；最终到达 `type: "end"`，该结束节点不填写 `next`。正式路线不能有孤立的专用节点、断开的跳转或无法通关的节点。
4. **准备新身份美术。** 先列出本路线必须交付的新身份立绘、表情、场景、CG、道具、变身特效和音频；已有共享素材可以复用。将图片导入 Unity，在 Inspector 将 `Texture Type` 设置为 `Sprite (2D and UI)`，独立图片使用 `Sprite Mode: Single`，点击 `Apply`。需要透明背景的立绘和道具应保留图片透明通道。音频导入后应能作为 `AudioClip` 选择和试听。
5. **绑定资源。** 选中该路线的 `resource-catalog.asset`，在 `entries` 中逐项填写 `id`、`kind`，将图片的 Sprite 拖入 `sprite`，将音频拖入 `clip`。没有目录时，在 Project 窗口使用 `Create → BaiguVN → Route Resource Catalog` 创建，并命名为 `resource-catalog.asset`。复制现有草稿则已有该目录。
6. **把资源用在节点上。** 普通换图使用节点的 `portraitId`、`backgroundId`、`cgId`；特殊演出放进节点 `actions`。资源目录、正文和 `requiredAssets` 必须使用完全一致的业务 ID。仅把一张图片放入文件夹，不会自动识别它的人物身份、表情或出场位置。
7. **检查并发布。** 真实图片和音频绑定完成后，将对应资源的 `placeholder` 取消。检查剧本和美术，设置 `artReviewed: true`，再改为 `status: "published"`。运行 Unity 顶部菜单 `BaiguVN → Routes → Rebuild Published Catalog`，在 Console 确认生成成功。
8. **进入游戏验收。** 重新进入 Play，打开 `Assets/_Game/Scenes/VNMain.unity` 对应游戏流程并开始新游戏，到首次选择处验证新增按钮、资源和通关。一次接入一个小功能，检查后连同相关 `.meta` 与生成输出一起做本地 Git 提交。

编辑器会监听相关源文件和资源变更并排队重建；进入 Play 和构建游戏前也会校验。手动菜单用于明确检查当前内容是否可发布，不需要手工制作新按钮。

### 资源登记规则

| `kind` | Inspector 中绑定的对象 | 节点中的常见引用 |
| --- | --- | --- |
| `portrait` | Sprite | `portraitId`、`transform.assetId` |
| `background` | Sprite | `backgroundId` |
| `cg` | Sprite | `cgId` |
| `prop` | Sprite | `prop.assetId` |
| `effect` | Sprite | `transform.effectId`、`flash.effectId` |
| `bgm` | AudioClip | `bgmId` |
| `se` | AudioClip | `seId` |
| `ambience` | AudioClip | `ambienceId` |

同一目录中的资源 ID 不能重复，即使类型不同也不能重名。路线专用资源也不能与共享目录重名；不能用重名来覆盖共享立绘。推荐前缀如 `fun_13_identity_neutral`、`fun_13_stamp`。

`requiredAssets` 是该路线必须交付的资源清单，可以包含正文尚未直接调用但发布前必须具备的素材。生成器同时扫描正文和动作里的资源引用，因此不要以为删掉清单项就能绕过缺图检查。`artReviewed` 是人工确认标记；工具能检查有没有图，不能判断画的身份、表情或构图是否正确。

所有正式资源登记项都必须完整且 `placeholder: false`。只有占位资源的路线保持草稿；当前正式运行菜单不提供“允许缺图强行发布”的开关。

## 动作配置怎么写

节点中的 `actions` 按顺序执行。上一段背景、CG、人物进出场完成后，再执行这些动作；动作完成后才允许继续推进和存档。

| 动作 `type` | 主要字段与行为 |
| --- | --- |
| `transform` | `assetId` 为新身份 `portrait`，`slot` 为左 `0`、中 `1`、右 `2`；可选 `effectId` 为变身特效图。有特效时先遮挡、换图、再散开；没有特效则直接替换。 |
| `flash` | `duration` 控制闪白时长；可选 `effectId` 使用一张特效图。显示层在剧情美术上方、菜单下方。 |
| `shake` | `slot: 0/1/2` 震动一个立绘，`slot: -1` 震动整幅剧情画面；`x/y` 表示横纵幅度，两者均为零时使用默认幅度，结束或取消后恢复原位置。 |
| `prop` | `instanceId` 标识屏幕上的道具实例，`assetId` 指向 `prop`；`x/y` 为以画面中心为原点的 UI 坐标，`scale` 控制相对于图片尺寸的缩放。同实例再次出现会更新该道具。 |
| `clearProp` | `instanceId` 删除指定道具，`"*"` 清除全部道具。普通道具不能取名为 `"*"`。 |
| `wait` | 使用 `duration` 等待指定秒数。 |

`duration` 使用秒，范围为 `0` 至 `10`；位置和幅度必须为有限数值，使用缩放的动作要求 `0 < scale <= 10`。变身特效的 `x/y` 是相对该立绘的偏移；道具 `x/y` 是屏幕中心坐标，二者不要混淆。

同一个节点不能一边用 `portraitId` 直接替换某槽位，又通过 `transform` 再变身同一槽位。需要这种先后变化时，拆成两个节点。持久道具和变身后的立绘会写入画面快照；烟雾、闪白、震动等短暂效果不会在读档时重新播放。

## 最小娱乐路线示例

下面只展示可接入的结构，不是正式分支剧本，也不会自动发布。建立目录 `fun_demo_identity`、添加对应资源目录，并准备以下三项真实 Sprite 后，才可以完成发布步骤。

| 资源 ID | 类型 | 要准备的图片 |
| --- | --- | --- |
| `fun_demo_identity_portrait` | `portrait` | 悟空新身份立绘 |
| `fun_demo_identity_smoke` | `effect` | 变身遮挡效果 |
| `fun_demo_identity_seal` | `prop` | 演示道具 |

`route.json` 内容：

```json
{
  "schemaVersion": 1,
  "routeId": "fun_demo_identity",
  "kind": "entertainment",
  "choiceGroupId": "first_encounter",
  "title": "身份变化演出示例",
  "choiceText": "变个身份，试一试新的办法。",
  "order": 200,
  "status": "draft",
  "entryNode": "fun_demo_identity_001",
  "contentRevision": 1,
  "artReviewed": false,
  "requiredAssets": [
    { "id": "fun_demo_identity_portrait", "kind": "portrait" },
    { "id": "fun_demo_identity_smoke", "kind": "effect" },
    { "id": "fun_demo_identity_seal", "kind": "prop" }
  ],
  "nodes": [
    {
      "id": "fun_demo_identity_001",
      "type": "line",
      "speaker": "孙悟空",
      "text": "且看俺老孙换个模样。",
      "actions": [
        {
          "type": "transform",
          "assetId": "fun_demo_identity_portrait",
          "effectId": "fun_demo_identity_smoke",
          "slot": 1,
          "duration": 0.6,
          "scale": 1
        }
      ],
      "next": "fun_demo_identity_002"
    },
    {
      "id": "fun_demo_identity_002",
      "type": "line",
      "speaker": "",
      "text": "悟空亮出一件道具。",
      "actions": [
        {
          "type": "prop",
          "instanceId": "demo_seal",
          "assetId": "fun_demo_identity_seal",
          "x": 260,
          "y": 0,
          "scale": 0.5
        }
      ],
      "next": "fun_demo_identity_end"
    },
    {
      "id": "fun_demo_identity_end",
      "type": "end",
      "speaker": "",
      "text": "演出结构示例结束。正式故事在此替换为自己的收尾。",
      "resultId": "fun_demo_identity_complete",
      "actions": [
        { "type": "clearProp", "instanceId": "demo_seal" }
      ]
    }
  ]
}
```

在资源目录中登记上述三个 ID 及真实图片，完成检查后再把 `artReviewed` 改为 `true`、`status` 改为 `published`，即可进入这三个节点验证。图片仍是占位时保持草稿，不把示例当作已经完成的娱乐故事。`resourceCatalogPath` 由生成器填写，不需要在作者 JSON 中手工指定。

## 增减选项与删除路线

| 操作 | 修改什么 | 重建后的菜单变化 |
| --- | --- | --- |
| 添加一条可玩路线 | 新增独立内容包并通过发布检查 | 自动多出一个选项 |
| 改选项文字、排序 | 修改 `choiceText`、`order` | 使用新文字和排列 |
| 暂时下架 | `status` 改为 `disabled` | 对应选项移除，作者素材保留 |
| 退回制作阶段 | `status` 改为 `draft`、按需要取消 `artReviewed` | 对应选项移除 |
| 正式移除 | 在 Unity 中移走整个内容包到源目录外，或移除该包的 `route.json` | 对应选项移除，生成器清理自己记录的资源副本 |

改变一个已发布路线的资源前，建议先改回草稿，修完后再发布。已发布路线突然缺图、跳转失效或出现重复 ID，会阻止整次重建，并阻止进入 Play 或构建，避免仍用过期菜单运行。Console 中的错误指出具体路线或资源；修复源文件后重新运行重建菜单。

生成器不会删除作者的原始美术，也不会删除 `shared.asset`。手动删除原图前检查其他资源目录和场景是否引用它；公共素材应该移入共享目录复用，不依赖另一条娱乐路线的私有资源。

## 存档兼容与稳定 ID

- `routeId` 是路线身份，不能根据菜单排序重编号。改名字、改按钮文字、调整顺序时保留它。
- 节点 ID 代表具体剧情位置。不要把已发布的节点 ID 重新分配给完全不同的剧情；结构或节点含义变化时提高 `contentRevision`，真正移除或替换的节点使用新 ID。
- 资源 ID 代表某种已约定的画面或声音。重绘同一身份、表情时保留业务 ID 并替换对应引用；新增不同身份或表情使用新 ID。通过 Unity 移动资源，保留 `.meta`。
- 增加其他路线或只改菜单文字不必让已有存档失效。运行系统根据路线、节点和资源能否继续使用判断，不把所有存档因版本号改变一起清空。
- `contentRevision` 用于记录修订，不是自动强制回档开关。同一个节点 ID 和资源 ID 都还有效时，已有稳定画面可以继续恢复；若剧情含义已经完全改变，应给新剧情使用新的节点 ID。
- 路线被停用、删除，或存档所在节点/资源不再可用时，系统提示并尝试恢复首次选择前的完整快照。没有有效检查点的旧存档会回到开场。读取时不覆盖原存档，继续推进或再次保存才写新状态。
- 演出尚未稳定时禁止存档，避免只保存半个变身。稳定后保存会包含背景、立绘、CG、道具和音乐标识；读档直接恢复这些状态，不重放已经结束的闪白或烟雾。

当前更新以停止 Play、编辑并重建、重新进入 Play/新游戏为界。已经发布的玩家版本需要重新构建并分发后获得新内容。本期没有线上热更新，也不承诺正在游玩的选项列表随编辑即时变化。

## 后续扩展到六个剧情节点

当前自动收集路线的主入口只有一个：第一次出手之前的 `first_encounter`。后续三次打妖怪与三次解释，可以在每条路线内部增加普通 `choice` 节点：不填 `choiceGroupId`，使用 `choices` 给出该路线里的分支目标，例如：

```json
{
  "id": "fun_13_explain_choice",
  "type": "choice",
  "text": "悟空准备如何解释？",
  "choices": [
    { "id": "explain_directly", "label": "先把事情说清楚。", "next": "fun_13_explain_a" },
    { "id": "show_the_prop", "label": "先拿出道具。", "next": "fun_13_explain_b" }
  ]
}
```

这段只是节点结构，接入时必须补齐两个 `next` 指向的正文和收尾。内部分支会继承娱乐路线身份，不会因为接入公共正文变成原著路线。不能把路线内部跳转回 `first_encounter` 重新选择别的路线，也不能直接跳进另一条路线的私有节点。当前工具不会自动替作者写出六组选项或分支剧本。

## 每条路线的验收步骤

1. 运行 `BaiguVN → Routes → Rebuild Published Catalog`，确认 Console 无目录校验错误，再进入 `VNMain` Play。没有名为“路线预览”的额外菜单；目前按正常游戏入口验证。
2. 到首次选择处核对按钮数量、顺序、长文字换行、鼠标滚轮/触屏拖动和键盘上下选择。重复点击只应进入一次路线；打开再关闭设置、历史或存档页后仍应能选择。
3. 逐段检查新身份、表情、背景、CG、道具和音效是否出现在正确节点。确认变身前后角色正确，烟雾消失、震动复位，道具不会沿用上一条路线的图片。
4. 在变身或背景过渡期间打开菜单，确认演出暂停；关闭菜单应恢复。演出期间存档应不可执行；稳定后保存再读取应恢复同一身份和道具。
5. 跑到结尾，确认本轮正常完成。娱乐线不应新增主线完成、纪念或收藏记录，即使复用带有 `B03` 的公共结尾也一样。
6. 保留测试存档，停用其路线并重建、重新运行，验证旧存档提示和选择前快照恢复。再恢复发布，确认对应按钮重新出现。
7. 在独立验收副本中准备十二条以上完整短测试路线检查长列表，不能为了测试数量把主工程的空草稿直接发布。实际按钮数等于已发布路线数，不等于草稿目录数。

自动校验与编译可以发现结构、引用和类型问题，不能代替最终美术预览。本次尚未完成真实设备上的画面、触屏、字体、遮挡、音量、内存和加载耗时验收；正式美术与分支接入后，需要按以上步骤在目标设备检查。

本次已在 Unity 6000.6.0f1 独立副本中完成 24 项原生集成检查，全部通过；十四选项列表的首尾截图也已检查。具体覆盖和内容边界见《多选项实现验收记录》。
